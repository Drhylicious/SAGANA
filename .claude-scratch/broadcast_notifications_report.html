Bug caught during a post-ship re-verification pass
  • The Compose success message chose "Scheduled for X" vs. "Sent to N recipients" based only on whether the Schedule toggle was on — not whether the picked time was actually still in the future. The date picker allows "today," and the time picker has no awareness of that selected date, so picking today + an earlier time produced a past scheduledAt. sendBroadcast() already handled this correctly (sends immediately, since isDeferred checks isAfter(now)) — only the confirmation wording was wrong. Fixed to check actual deferral instead of just the toggle. Cosmetic only: no broadcast was ever mis-delivered because of this.

How to test

  3. Open Broadcast History immediately. Expected: the scheduled item shows as pending (not crashed), labeled with its scheduled time.
  4. Wait until the scheduled time passes (~5 min for the next cron tick), then check the recipients' notifications. Expected: the notification has now arrived, and the History entry shows as sent.

Bug caught mid-phase
